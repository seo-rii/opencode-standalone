# Actual OpenTUI JavaScript factory integration

This profile connects the published `@opentui/core` 0.6.6 classes to a checked WASM backend. The real `createTestRenderer`, `CliRenderer`, `NativeSession`, `NativeScene`, Box/Text/Input/Textarea, Code, Markdown, TextBuffer/TextBufferView, and SyntaxStyle run through this boundary. It is separate from the existing computational checkpoint and powers the original default and mini CLI interfaces.

`published-sources.json` pins the actual package entry points and shared JavaScript chunks. `package.mjs` verifies those hashes before selecting the WASM factory and adapting four cell-array views plus the raw image lease view to linear memory. Upstream scene staging, frame scheduling, input parsing, renderable behavior, buffer-access guards, and errors remain in the actual package code. The adapter borrows the original StyledText, editor-style, selection, program-status, buffer-drawing and image-drawing encoders so those records retain upstream validation and metadata. Missing backend operations throw `NativeError(UnsupportedResource)`.

Each public Context has a distinct opaque JavaScript identity and its own reactor. Handles from independent reactors can have the same numeric context ID, so routing also verifies their public owner identity. Frame and output tickets retain their upstream 64-bit fields as decimal strings across JSON. Packed RGBA lanes retain their metadata.

The real native `ot_scene_flush` parser applies the upstream staged-property byte format and reports its accepted prefix. The adapter consumes that prefix using the actual `SceneStaging` object. Real frame tickets are committed into the upstream Session feed; the original `NativeSession` driver pumps, copies, writes, and acknowledges output through its configured memory sink.

`editor.mjs` connects real edit buffers, views, history, ranges, selections, placeholders, syntax styles, and highlights. Native content/cursor callbacks enter a bounded reactor queue; the JavaScript adapter checks the native handle generation and forwards them with the original microtask listener semantics. Keyboard and bracketed paste tests use the actual published input parser and Input class.

`session.mjs` connects terminal setup, title/control packets, suspend/resume, and restoration. These use the actual Session lifecycle and acknowledged output tickets. Owned `OptimizedBuffer` drawing and composition in `buffer.mjs` use the checked C ABI and native storage, including scoped writable leases. Custom Renderable paint hooks use the original host recorder and native record playback. ScrollBox uses real native viewport clipping, translated content, sliders, and arrows. Detached snapshot copying and split-footer scrollback commits use real buffers and Session output. `text.mjs` connects shared text resources to the same Context and is exercised by actual Code/Markdown highlighting with the embedded parser worker.

`terminal.mjs` connects all 17 embedded-terminal methods to the original checked EmbeddedTerminal and compositor, with OpenTUI's pinned Ghostty VT compiled into the factory. The actual EmbeddedTerminalRenderable retains its custom paint, layout, focus and input handling. Its resource handles, frame tickets and generation-checked binary spans use the same Context ownership rules as other resources. Original 1 MiB write chunks preserve streaming UTF-8/escape sequences; the native response queue retains its 1 MiB bound and the original JavaScript retry on backpressure. Selection text and encoded input are copied before releasing native output. Session cursor control sends the original packed cursor record through the checked Session control ABI.

Buffer leases expose actual linear-memory offsets. The four adapted typed-array constructors use Node 26.4's resizable WASM buffer so valid scoped views survive memory growth. They alias the native cell planes, preserve the original synchronous callback guards, and validate/release the real checked lease. No snapshot array replaces writable cell storage.

`measure.mjs` registers custom measurement providers with the real Context/Yoga nodes. A fixed WASM import carries the native handle, floating-point constraints, and Yoga modes to the original JavaScript provider, then writes its two result dimensions into a checked eight-byte memory window. The original YogaHost rejects mutation and asynchronous callbacks, defers provider exceptions until native cleanup, and cancels an accepted frame after a callback error. Seven checked scene queries may run synchronously inside a measurement; the reactor owns each request's parsed strings and preserves the suspended call's status. Other reentry is rejected before it can overwrite transport memory. Removing providers and destroying nodes, sessions, or contexts releases their registrations.

From `standalone/tui` after preparing the pinned compiler/source overlay:

```sh
node factory-build.mjs
node backend/build.mjs
node --experimental-ffi --test --test-concurrency=2 backend/*.test.mjs
```

The default package bundle is `.cache/backend/core.mjs`. It contains the actual published JavaScript and the generated factory WASM. Tests use separate artifact names so parallel files do not overwrite each other's bundles. All 28 focused renderer/text/measurement/StyledText tests pass. They cover narrow/wide layouts, Unicode and styled links, mutation, resize, real cell-plane aliases, native editor events and history, keyboard/paste input, acknowledged terminal transitions/restoration, recorded custom painting, clipped scrolling, split scrollback, shared highlighted text, custom measurement with nested native reads and failure recovery, the actual upstream SpinnerRenderable, cross-context rejection, empty/conditional StyledText chunks, public edit measurement, and copying one module into an empty directory with `PATH` empty and native addons disabled. Two additional host tests verify input flushing against a real kernel PTY and the upstream best-effort behavior for non-terminal descriptors. This host path lazily uses Node's built-in FFI and system libc; ordinary memory-only rendering does not load it.

`production.test.mjs` adds actual Solid signals, streaming Markdown/code highlighting, scroll/resize, route unmount/remount, focused Korean editing and real parser worker cleanup. `image.mjs` connects the published NativeImage/NativeImagePool/ImageRenderable classes to actual PNG/JPEG/GIF/WebP codecs, LittleCMS ICC conversion, resizing/compositing and scoped pixel leases. Cross-reactor clones preserve metadata, lazy state, original PNG bytes and decoded pixels; rendering retains resources after source disposal. Five public image tests include copied one-JS execution with an empty PATH and native addons disabled. Large-image cases exercise a PNG over 4 MiB, 67,125,248-byte raw images, padded readback, pooled updates, resizing and memory growth with a live pixel lease. The separate codec profile has three tests and a 294-request native comparison with 25 captures.

Images use separate generation-checked binary windows instead of base64 JSON. Input spans carry a relative offset, length and reserve generation; output spans carry a linear-memory offset, length and output generation. The synchronous read callback consumes outputs before another native call or release can invalidate them. Cross-Context copies use 256 KiB chunks without a full intermediate JavaScript image allocation. Pixel readback allocates only the row prefix needed by the caller, preserves padding/tails, and PNG readback borrows the actual encoded native image. `binary.test.mjs` exercises stale generations, invalid ranges, oversized admission, short destinations, minimal allocation and output expiry through the actual reactor exports.

Four public terminal tests cover actual ANSI/Unicode cells and colors, selection, scrollback, resize, key/mouse/paste/focus encoding, queued responses, stale/cross-Context resources, cursor focus/blur and custom paint at 44/100 columns. One copies the bundle into an empty directory with PATH empty and addons disabled. The complete copied-CLI test additionally opens the original /terminal pane against a real persistent PTY, prints Korean text, resizes, hides/reopens with the same shell PID and replayed screen, and exits the shell. `../terminal/sources.json` pins Ghostty commit 727b8a02f8734840de664c060678dd66f01931f6 and its archive; its reported version 0.1.0-dev+b988efcf is not the source commit. Native comparison tooling is development-only.

Linux OS clipboard operations run through `../clipboard.mjs` and the direct X11/Wayland providers, keeping the published clipboard APIs, validation and destination policies. Their image reads preserve encoded PNG/JPEG/WebP/GIF bytes without decoding or imposing renderer pixel limits. Actual Xvfb/Xlib and headless Sway/native-client tests exercise host selection ownership, read/write/clear, primary, bounded and incremental transfers, deadlines, cancellation and disposal. The copied original application adapter also verifies text/PNG paste and host copy alongside the actual Session OSC 52 output. No native clipboard library or command is required at runtime; see [../clipboard/README.md](../clipboard/README.md).

The factory grows on demand to a 1 GiB memory ceiling, with separate 256 MiB input/output budgets. Upstream encoded 64 MiB, decoded 100 MiB, 25-million-pixel and 16,384-dimension limits remain unchanged. Aggregate images and extreme row padding can still exceed the factory budgets and fail explicitly. The independent computation/image profiles retain their 64 MiB ceiling and bounded base64 proof API. The original terminal's direct-only Kitty restrictions and absence of Kitty placement drawing remain unchanged. Audio playback, other clipboard platforms and unsupported operations still need implementations. Terminal OSC 52 is connected. Passing these focused tests does not establish complete OpenCode feature or platform parity.
