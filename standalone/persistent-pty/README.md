# Standalone persistent terminals

The Node executable dispatches `--standalone-persistent-pty-daemon` before loading the application. Its daemon implements opencode-pty protocol 7 over a private Unix socket, including authenticated ownership, one-use restart tickets, controller and observer attachments, byte offsets, replay, resize checkpoints, snapshots and physical row reads. It creates real Linux PTYs using the standalone Node FFI adapter. Terminal processes keep their PID when the application server transfers ownership to its replacement.

`service.json` and `service.lock` live in `<runtime-dir>/<name>`. The registration and socket have mode `0600`; the runtime directory has mode `0700`. A kernel `flock` prevents concurrent daemons in one directory, follows registration migration, and releases automatically after process death. An unclaimed daemon exits after five seconds. Disconnecting its owner terminates the daemon and terminals unless a prepared handoff remains valid; a handoff expires after 120 seconds without renewal.

Output replay retains the latest 2 MiB of bytes. Frame payloads are limited to 8 MiB, input to 1 MiB, and row responses to 1 MiB. A slow controller pauses PTY reads; an observer whose pending socket output exceeds 8 MiB is disconnected. Closing the controller promotes the attachment that most recently controlled the terminal.

The build embeds the real Ghostty WASM asset from `anomalyco/ghostty-web` revision `83c0a07b8628b748aed073b232cb4b52a6ca11c1`. `terminal.ts` calls its C ABI directly and discovers structure layouts through `ghostty_type_json`; snapshots and checkpoints come from Ghostty's formatter, and terminal device replies return to the PTY. This asset is pinned independently from the native Ghostty revision used by upstream opencode-pty, so terminal emulation is not guaranteed to match that native build byte for byte. Source tests load the same package asset when the build-only virtual module is unavailable.

The implementation has Linux x64 and arm64 ABI paths; validation is on Linux x64, and arm64 remains unverified. It requires kernel 5.4 or later, Node 26.4 or later and `--experimental-ffi`. Windows and macOS fail explicitly. Cleanup retains process identities with pidfds, adopts orphaned jobs and reaps those exact handles; it never signals a stored numeric process group after the shell exits. Descendants that deliberately create another session fall outside this ownership boundary. Foreground-process metadata reports Linux's foreground process-group leader; it does not implement upstream's ranking among deeper descendants. Screen state and replay live in the daemon process and survive application-server handoff, but they do not survive daemon termination or a machine restart.
